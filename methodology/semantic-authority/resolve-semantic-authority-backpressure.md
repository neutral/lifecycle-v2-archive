# Resolve Semantic Authority Backpressure

## Purpose

Use this operation when work cannot safely proceed because product meaning is
missing, stale, contradictory, or owned by the wrong semantic authority surface.
If the missing item is product judgment rather than durable product meaning,
return to Work Boundary framing instead of creating a semantic authority entry.
If the missing item is Context scope, route, review depth, freshness, or
canonicalization, return to Clarity instead of hiding that gap in a later
surface.

## Procedure

1. Name the blocked state and the decision that cannot be made.
2. Name the missing or conflicting product meaning.
3. Identify the semantic authority surface that should own the meaning.
4. If the owner is Context and the gap is a Context maintenance problem, route
   to Clarity or update the active Clarity Boundary when Clarity is active.
5. If the owner is clear and admission exists, update product meaning.
6. If admission is missing, ask, reframe, split, defer, or abandon the work.
7. If no installed surface owns the meaning, record the methodology or surface
   gap in `.lifecycle/scratch/` or the active Control record.
8. If product authority is sufficient but product judgment is missing or
   falsified, update the active Work Boundary rather than semantic authority.

## Output

The active Control record should show the backpressure cause, owner surface,
response, and next state.

## Failure Route

Do not proceed by treating chat history, proof output, product judgment, or
process records as durable product authority.
