# Clarity Control Records

## Purpose

Use this folder for process-local Control records that Clarity creates and
updates.

Clarity records preserve Context-pass state. They do not become Context
semantic authority. Future agents rely on updated Context entries for product
meaning and on Clarity records for process history, review evidence, and
recommendations.

## Records

Clarity uses:

```text
Clarity Boundary
Source Inventory
Context Review Packet
Clarity Closure Record
```

Use [clarity-boundary.md](clarity-boundary.md) before Context edits.

Use [source-inventory.md](source-inventory.md) before importing or reshaping
source material.

Use [context-review-packet.md](context-review-packet.md) for route, content,
canonicalization, promotion, and retrieval checks.

Use [clarity-closure-record.md](clarity-closure-record.md) to close without
starting another process.

## Authority Rule

Clarity may update Context through an active Clarity Boundary. It may not
admit behavior, authorize Build, select the next Signal automatically, or treat
recommendations as handoffs that start another process.
