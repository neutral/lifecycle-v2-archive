# Clarity

## Purpose

Use Clarity when Context itself needs bounded work.

Clarity builds and maintains the Context semantic layer so Discovery can select
well and Delivery can admit work from a coherent product world. It is governed
by a bounded Clarity Boundary, live review state, and explicit closure
recommendations.

## When To Use

Start Clarity when:

```text
Context is missing, stale, flat, duplicated, contradictory, or hard to retrieve
a broad product question needs Context before action
a Context cluster needs review, canonicalization, or supersession decisions
promotion pressure toward Intent, Assurance, Blueprint, or Description is
accumulating
Discovery cannot select useful work because product direction is vague
Delivery is blocked by missing rationale, product posture, or scope boundaries
```

Do not start Clarity when a concrete selected Signal is already ready for
Delivery and current Context is sufficient.

## Output

Clarity produces:

```text
updated Context entries
route and review labels
canonical Context references
stale, duplicate, conflict, or supersession decisions
promotion pressure
retrieval proof
recommendations for founder-dev inspection
```

Clarity does not automatically start Discovery or Delivery. Recommendations
remain recommendations until the founder-dev decides what process should start
next.
