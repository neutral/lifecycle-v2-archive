# Content Adequacy Review

## Purpose

Use Content Adequacy Review to decide how strongly Context leaves can govern.

Route adequacy is not content adequacy. A route can be current while leaves
remain unreviewed.

## Questions

Answer for each scoped entry:

```text
What meaning does this entry own?
Is it current, provisional, stale, superseded, or archived?
Is review_status honest?
Is freshness honest?
Is it canonical, rationale, glossary, design reference, proof context,
delivery posture, open question, or topic leaf?
Does it duplicate, contradict, or depend on another entry?
Does it pressure Intent, Assurance, Blueprint, or Description?
```

For broad Context clusters, also answer:

```text
What product area does this serve?
What overview routes future agents here?
Which entry is canonical for current posture or direction?
Which entries are supporting rationale, examples, history, or references?
What is stale, duplicated, contradictory, or source-shaped?
What future Intent, Assurance, Blueprint, or Description should this Context
pressure but not own?
```

Do not let the review inherit source file boundaries by default. Keep,
reshape, split, merge, defer, or reject source material according to the current
target product meaning and the review depth in the Clarity Boundary.

## Exit

Exit when every entry in scope has an honest state, review label, freshness
label, and relation treatment for the selected review depth.
