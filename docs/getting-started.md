# Getting started

Lifecycle has one Delivery Process. A Founder frames an exact objective;
preparation observes the repository and proposes a Work Boundary;
authenticated admission makes that mandate active; funded Agent Attempts
produce work inside it; evaluation seals and checks the exact Candidate with
independent review; and an authenticated acceptance or no-ship decision closes
the Delivery. Recovery continues retained Process or cleanup work without
inventing a second process.

The central invariant is that only admitted behavior can ship. Project
meaning, semantic authority, reversible Candidate work, runtime observations,
Evidence, and canonical repository movement remain distinct throughout the
route. The normative model is in
[`spec-source/SPEC.md`](../spec-source/SPEC.md).

## Target boundary

Use Lifecycle with a separate Git repository. Every target provides a
complete, valid, Founder-maintained Atlas rooted at tracked regular file
`atlas/atlas.md`. Lifecycle reads that Atlas under the Foundation contract and
does not author or repair it.

Start with [installation](installation.md) to build the Foundation core.
