# Getting started

Lifecycle has one Delivery Process. The Director supplies the intended result
and boundaries; the Worker gathers supporting information and performs
authorized work. Either role can be human or agent.

Preparation observes the repository and proposes a Work Boundary.
Authenticated admission makes that exact Boundary active. Funded Agent Attempts
produce work in a retained Candidate; integration constructs its result against
one exact canonical parent. Evaluation seals and checks the Candidate with
independent review. An authenticated acceptance or no-ship decision closes the
Delivery. Recovery continues exact retained obligations.

The central invariant is that only admitted behavior can ship. Project
meaning, semantic authority, reversible Candidate work, Runtime observations,
Evidence, and canonical repository movement remain distinct throughout the
route. The normative model is in
[`spec-source/SPEC.md`](../spec-source/SPEC.md).

## Target boundary

Use Lifecycle with a separate fresh Git repository. Every target provides a
complete, valid, Director-maintained Atlas rooted at tracked regular file
`atlas/atlas.md`. Lifecycle reads that Atlas under its exact
[Atlas contract](../spec-source/spec/ATLAS.md) and does not author or repair it.
Repository contract v22 supports fresh initialization; predecessor and mixed
state are refused.

Start with [installation](installation.md) to build the Foundation core.
The [Runtime overview](../runtime/overview.md) explains initialization,
private custody, CLI operations, and the execution prerequisites.
